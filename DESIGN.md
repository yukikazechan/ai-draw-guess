# Existing visual system

Invitation failures remain visible next to the join form and preserve the invite code in the URL and input. Late arrivals see the shared arena as spectators, with “本局观战 · 下局自动参赛” in the member list, action panel and mobile status. Room chat uses the existing conversation panel and drawer, a labelled input and an intrinsic send button; it remains available between games and marks spectator messages. It is separate from post-reveal targeted AI banter. The member cap remains eight, including spectators waiting for the next match.

The game inherits the existing WenKai font, light blue ground, navy text, blue primary controls and white drawing surface. Secondary text uses #58677f. Solo and online matches share one board: a large canvas and action panel on the left, compact Live2D seats and the conversation on the right. Seats show the configured model, score, status, model-reported confidence and published answers from each completed guess round. The artist has a warm cream surface; correct and incorrect guesses also carry text marks, not only color.

At widths up to 800px the same seat nodes move into a horizontal, paged strip below the header, two participants per page. Native touch swipes, mouse dragging, keyboard arrows and snap scrolling change pages; dots and a page count are passive indicators. A new question initially brings its artist into view; score updates preserve the reader's current page. Offscreen Live2D render loops pause. The canvas and answer controls follow the strip; conversation remains below. The incomplete-resource notice becomes a compact disclosure on phones during a match. Account and admin forms live at `/online?account=1`; `/online` resumes the shared game interface after authentication.

Drawing tools include a seed-based paint bucket. Its operations remain ordered alongside strokes for undo, synchronization and replay. Guess text is published after collective scoring, with turn number, correctness and earned points; new submissions stay private until their round is scored. Confidence percentages are model self-reports, not calibrated win probabilities. No generated or downloaded raster artwork was added by this integration.

During mobile room matches, the room code shares the top bar. Invite, leave, account and resource help share a compact bottom dock with safe-area padding; no room-information block separates the seat strip from the canvas. Native momentum and snap scrolling drive touch paging. Mouse dragging batches updates into animation frames and uses distance/velocity to select the next page.

The mobile match now fits a dynamic viewport workspace. The footer changes from drawing submission to guessing input to round progression with the phase. Hints, full messages and detailed controls open the existing focus drawer; nonessential copy does not lengthen the match page. The roster defaults closed during drawing and open while guessing or judging. Room codes and secondary actions remain compact, and a server-synchronized countdown is visible only while a human drawing/guessing deadline is active. AI waits retain their provider timeouts. Empty human drawing timeouts award the artist zero and every opponent three points for the question; human guess timeouts earn zero.

The lobby displays exactly the selected AI models in a preview grid below setup. These are the same seat and Live2D nodes used in the match; there is no standalone automatic companion selector on the main page. Room invitations use a blue primary action with explanatory copy; human members have initial avatars, names, presence, host labels and a visible capacity count. On phones the active room's header button reads “成员 N · 邀请” and opens a member/link dialog. Expanded chat is capped at 1080px on desktop, with 17px message text, an uncapped flexing log, and its footer anchored to the bottom; the 220px arena preview cap does not apply in the drawer.

After full question reveal, the chat exposes a targeted participant composer and the named human's reply form. Targets include other humans and AI: humans reply themselves, and only AI targets call a model. Automatic AI challenges use real submissions and may also address a correct human response. In rooms with multiple humans, an unsolved viewer receives only published wrong guesses; correct guess text and reasons remain server-filtered until that viewer solves or the question is revealed. Solo modes keep the original disclosure behavior. “提交答案” is the dominant primary action; “跳过” is a compact secondary action in the same row. The form uses a bounded input track and intrinsic button widths; full-width primary styling applies only to direct action-panel children. AI revision and shared guess start run on server deadlines; humans retain control of their own revisions.

Chat follow state tracks deliberate scrolling, not scroll events caused by message insertion, form changes or resizing. The expanded chat keeps its footer anchored while the log consumes remaining height, including when the participant composer switches from a reply form to a new-message form.
