# Existing visual system

Room recovery controls use the same role-aware state on mobile and desktop: a spectator who becomes host retains next-question/result and drawing-retry actions without becoming a guesser. Returning to preparation preserves the current AI selection unless its owner changed. While reading chat history, a pending response becoming a reply, error or cancellation exposes a new-response cue without moving the reader.

The resource notice is collapsed by default. Failed Live2D loads use a compact name initial and a separate 44px retry target; they do not compete with the game status. At 801–1200px the roster uses two columns for readable captions. Narrow drawer answer forms put the input on its own row, with the primary submit action wider than skip. The mobile workspace reserves the actual measured dock height. Auxiliary setup text uses the shared muted color, and keyboard focus uses a consistent visible outline.

Human answers have a per-question/attempt submission lock independent of long-running AI requests. An AI response gets a named pending row in the existing conversation; the eventual model line uses the same UI identity. Failed or cancelled requests remain explicit, retries return to pending, and human recipients never get fabricated model status. This applies to solo banter, shared room banter and lobby AI chat. AI guess seats distinguish automatic retry from normal processing and show failed submissions as zero points. A room host's reconnect grace appears in the same chat surface.

Answer privacy applies equally to solo and online human guessers: until solved or fully revealed, correct guesses and their reasons are filtered by the server, including redraws. Artists and pure AI spectators can inspect published guesses.

Room member cards expose a compact “移除” action only to the host; a confirmation explains whether removing that member ends the current match. The sound control uses an authored speaker icon in the existing desktop navigation and a labelled item in the mobile More menu. Sound cues are short synthesized notes, unlocked by a gesture, with a persistent mute preference; they do not replay historical messages or signal another player's hidden answer.

AI chat messages show pending, failed or cancelled delivery on their original row. Delivery changes update the existing message node. Responses remain associated with the actual target model, and unrelated lobby selection updates do not cancel an in-flight first response. Content-versioned module paths keep host and guest code aligned; an outdated client displays a refresh action.

Before a match and on the finished-match page, the same room composer lists AI models from the host's selected lobby roster and sends to the lobby conversation endpoint. It retains the selected recipient during replies, labels AI responses with their actual model, exposes retry for the sender/host, and explains that AI can be addressed before starting. No second form or separate chat screen is added. During a match the composer returns to the existing reveal-only AI interaction rules.

The message recipient stays selected across an AI response so follow-up lines remain addressed to that AI. While it responds, only sending to that selected AI pauses; the recipient control still allows ordinary human chat. Host changes update results-page actions immediately and reset lobby choices to the new host's own model configuration. Spectators do not see export links they cannot access.

Room members share the host's selected AI preview before each match, including character and actual model label. Selection updates arrive through room state; credentials and endpoint URLs are excluded. The ready room keeps chat visible. During room play, one composer handles public chat, human mentions, AI challenges after reveal, and replies when the viewer is addressed. Desktop uses recipient, expanding input and send button on one row; mobile puts the recipient above the input/send row. AI waits leave ordinary human chat available. A versioned room stylesheet refreshes the updated layout on deployments with cached CSS.

Invitation failures remain visible next to the join form and preserve the invite code in the URL and input. Late arrivals see the shared arena as spectators, with “本局观战 · 下局自动参赛” in the member list, action panel and mobile status. Room messages use the existing conversation panel and drawer; they remain available between games and mark spectator messages. Chat and post-reveal targeted AI banter share a composer. The member cap remains eight, including spectators waiting for the next match.

The game inherits the existing WenKai font, light blue ground, navy text, blue primary controls and white drawing surface. Secondary text uses #58677f. Solo and online matches share one board: a large canvas and action panel on the left, compact Live2D seats and the conversation on the right. Seats show the configured model, score, status, model-reported confidence and published answers from each completed guess round. The artist has a warm cream surface; correct and incorrect guesses also carry text marks, not only color.

At widths up to 800px the same seat nodes move into a horizontal, paged strip below the header, two participants per page. Native touch swipes, mouse dragging, keyboard arrows and snap scrolling change pages; dots and a page count are passive indicators. A new question initially brings its artist into view; score updates preserve the reader's current page. Offscreen Live2D render loops pause. The canvas and answer controls follow the strip; conversation remains below. The incomplete-resource notice becomes a compact disclosure on phones during a match. Account and admin forms live at `/online?account=1`; `/online` resumes the shared game interface after authentication.

Drawing tools include a seed-based paint bucket. Its operations remain ordered alongside strokes for undo, synchronization and replay. Guess text is published after collective scoring, with turn number, correctness and earned points; new submissions stay private until their round is scored. Confidence percentages are model self-reports, not calibrated win probabilities. No generated or downloaded raster artwork was added by this integration.

During mobile room matches, the room code shares the top bar. Invite, leave, account and resource help share a compact bottom dock with safe-area padding; no room-information block separates the seat strip from the canvas. Native momentum and snap scrolling drive touch paging. Mouse dragging batches updates into animation frames and uses distance/velocity to select the next page.

The mobile match now fits a dynamic viewport workspace. The footer changes from drawing submission to guessing input to round progression with the phase. Hints, full messages and detailed controls open the existing focus drawer; nonessential copy does not lengthen the match page. The roster defaults closed during drawing and open while guessing or judging. Room codes and secondary actions remain compact, and a server-synchronized countdown is visible only while a human drawing/guessing deadline is active. AI waits retain their provider timeouts. Empty human drawing timeouts award the artist zero and every opponent three points for the question; human guess timeouts earn zero.

The lobby displays exactly the selected AI models in a preview grid below setup. These are the same seat and Live2D nodes used in the match; there is no standalone automatic companion selector on the main page. Room invitations use a blue primary action with explanatory copy; human members have initial avatars, names, presence, host labels and a visible capacity count. On phones the active room's header button reads “成员 N · 邀请” and opens a member/link dialog. Expanded chat is capped at 1080px on desktop, with 17px message text, an uncapped flexing log, and its footer anchored to the bottom; the 220px arena preview cap does not apply in the drawer.

After full question reveal, the chat exposes a targeted participant composer and the named human's reply form. Targets include other humans and AI: humans reply themselves, and only AI targets call a model. Automatic AI challenges use real submissions and may also address a correct human response. An unsolved human viewer receives only published wrong guesses; correct guess text and reasons remain server-filtered until that viewer solves or the question is revealed. “提交答案” is the dominant primary action; “跳过” is a compact secondary action in the same row. The form uses a bounded input track and intrinsic button widths; full-width primary styling applies only to direct action-panel children. AI revision and shared guess start run on server deadlines; humans retain control of their own revisions.

Chat follow state tracks deliberate scrolling, not scroll events caused by message insertion, form changes or resizing. The expanded chat keeps its footer anchored while the log consumes remaining height, including when the participant composer switches from a reply form to a new-message form.
