# 消息、音效与房间管理验收

## 修复与服务端证据

用户提供的诊断显示：Gemini 三次实际等待约 60000ms 后超时，成功调用约 7–11 秒；另有 Claude 无效 JSON、MiniMax HTTP 400。没有将这些情况归咎于界面，也未修改用户的模型时限或调用真实付费接口。

另复现了一条应用侧路径：准备名单的公开型号元信息落后于已保存配置时，首次信息同步会取消正在调用当前正确型号的首条消息。现在按本次请求实际选用的型号签名判断，补齐元信息或增减其他 AI 不会取消它。原消息保留 pending/error/cancelled/replied 状态，失败分类不反射任意上游文字。兼容旧页面发送路径，由服务端识别 AI 收件人。

“默认加入比赛”从手动选择、房间预览和开局资格判断中分离。HTTP 验收将模型设为 enabled=false，确认起初未勾选，然后手动选择、准备聊天及开局均成功，模型和 Key 仍来自房主。内容版本目录覆盖主脚本与其相对模块导入；HTML 不缓存，接口返回版本信息，旧客户端发现不一致时提示刷新并停止旧连接。版本样式地址的 MIME 和返回内容也已验证。

## 房主与浏览器实际操作

- 使用本地模拟管理员作为房主登录；未默认勾选的 DeepSeek 点选后保持选中，下方预览从一位变为两位，并出现在发送对象中。房主首句发送到该模型即收到回应，发送者、对象和实际型号正确。
- 静音前 Web Audio 状态为 running。静音后继续聊天成功，音频调度计数保持 4 不变；重新打开音效后可正常触发，开始比赛的最后一项音效为 start。
- 房主确认移除未连接的模拟成员，人数从两人降为一人。用该成员的会话重新加入返回 400“已被房主移出该房间”。另有回归覆盖非房主无权移除、自身不能被该入口移除、移除参赛者结束比赛及移除观众不影响比赛。
- 手机 390px 无横向溢出，“更多”包含音效开关；桌面音效按钮可见。截图位于工作区根目录 `ai-draw-guess-audio-mobile.png`、`ai-draw-guess-audio-desktop.png`。截图接口在一次桌面 viewport 捕获中截取了局部画面，未将其当作完整桌面视觉证据。
