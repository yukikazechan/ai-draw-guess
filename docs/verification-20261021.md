# 2026-10-21 稳定性与互动状态验收

## 真人先交卷卡死

原路径：非联机 draw-done 等待全部 AI 返回，前端 inFlight 阻止真人 guess，但表单已禁用提交按钮，后续缓存渲染不恢复按钮。现在 startGuess 同步校验并进入 guessing，AI 后台执行；前端只锁定本人的同题同轮提交，失败恢复表单，猜词不等待绘图录制上传。下一题、改画和重试也不再让 HTTP 请求持续等待模型。

HTTP 回归将本地兼容模型挂起：draw-done 提前确认，真人先交卷成功，重复提交拒绝，解除挂起后自动判分且只有一条真人记录。浏览器在相同条件下实际点击提交，看到本人“已提交 · 等待揭晓”和 AI“模型处理中”；解除挂起后进入 review，全程没有刷新。

## 恢复、断线、保密

临时故障最多自动重试一次。测试覆盖成功单次计分、仍失败本次零分、下一轮恢复、取消后不再调用、AI 作画仍失败结束本题及配置错误不重试。取消信号可中断重试等待。现有绘图格式修复仍独立保留。

房主移交测试覆盖多标签、重连取消、重连期限不被状态更新重置、优先在线参赛者、本局 run 和倒计时保持、原房主失去控制权、下一局配置变更、观众接任但不计分，以及关闭房间时清理计时器。模拟时钟期限用于测试，不需要实际等待 30 秒。

答案保密覆盖非联机人机比赛、单真人和多真人房间、补画、猜中后开放、三轮后揭晓及历史题目记录。修正了原纯 AI 观战测试缺少模拟绘图回复的问题。

## AI 正在回应

从公开互动状态生成占位，不伪造模型发言。等待和实际回复共享 UI 标识，成功后替换，失败、重试、取消均有状态；准备聊天也覆盖，真人收件人不生成 AI 占位。浏览器实际发起 @Gemini，对话记录显示“Gemini 正在回应…”，放行本地模型后只留一条实际回复，aria-busy 节点从 1 变为 0。
