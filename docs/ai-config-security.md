# 纯网页、多设备与 AI 配置加密

此版本只需浏览器。每个账号在“我的 AI”或游戏右上角“AI 设置”填写自己的模型、接口和 Key。换手机、平板、电脑后登录同一账号即可继续使用，不需要安装扩展、运行额外服务或重新配置 Key。

## 哪个账号承担调用

房间开局时复制房主的 AI 配置，整局使用该快照。其他人加入时不提供 Key，也不会调用其他成员的 AI。个人的人机对局使用本人的配置。修改设置会在下一场比赛生效。

“统一 OpenRouter Key”只统一当前账号的 OpenRouter 选手；不同账号独立。管理员的环境变量 Key 及旧本地配置仅迁移到首位管理员，不提供给普通账号。选手单独保存的 Key 优先于本人的统一 Key，留空保留已有 Key，更换接口目标时不会把旧 Key 自动带到新目标。

管理员可点击“将我的选手设为新用户模板”，发布模型、接口、角色等默认值。模板不含统一或单独密钥，仅用于尚未初始化个人配置的新账号；已经保存配置的账号不被覆盖。

## 加密方法与安全边界

SQLite 的 `user_ai_configs` 表保存 AES-256-GCM 密文，整份个人 AI 配置一起加密。每次保存使用新 nonce，认证数据包含用户 ID，密文不能换到其他账号继续解密。API 的读取和保存响应只返回 `hasKey` 状态，不回显 Key。

主密钥是服务器持有的随机 256 位密钥，不从登录密码派生。因此用户换设备、改密码、管理员重置密码后，已有 AI 配置仍可继续使用。

这能保护其他账号访问和数据库单独泄漏，不能防止搭建者取得明文：调用模型时服务器会解密，拥有代码、进程或主密钥控制权的运维能够读取 Key。请只在信任的站点保存 Key，并在模型供应商处配置金额预算。

## 主密钥管理

默认首次启动自动创建 `.local/config-master.key`，Unix 文件权限为 600。无需手动配置即可使用。

若希望主密钥与数据库备份分开，部署前生成 32 字节随机密钥，通过服务器安全的环境配置设置 `CONFIG_ENCRYPTION_KEY`（Base64 或 64 位十六进制）。不要放进公开源码、网页或共享截图中。以后必须使用同一个值；直接更换会使旧配置无法解密。

已有加密配置但主密钥文件缺失时，服务拒绝生成新密钥覆盖旧配置。主密钥错误或密文被修改时，读取会报错，保留原密文。请恢复正确主密钥或完整备份。

停止服务后备份整个 `.local/`、`.env` 和外部管理的主密钥。SQLite 使用 WAL，不能仅复制一个正在写入的 `accounts.sqlite`。完整备份如果同时含主密钥，也应按明文凭证的敏感级别保护。丢失主密钥不能由重置账号密码恢复。

## 旧版本迁移

首位管理员首次读取个人配置时，旧 `config.json`、`credentials.json` 和原环境变量中的有效 Key 迁移到该管理员的加密配置，原 JSON 凭证文件随后脱敏。新用户不继承这些 Key。旧 `.env` 本身不自动删除，请按服务器凭证文件保管；迁移后账号设置为准。

普通账号可使用公网 HTTPS 模型接口。为保护服务器，不能访问本机、内网或保留地址，也不能使用服务器上的 Codex。管理员仍可使用自己信任的本地接口。接口连通性、识图和绘图能力可在设置页通过两次模型调用验证。
